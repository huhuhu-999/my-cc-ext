# 设计文档骨架模板

提供本插件标准的设计文档骨架模板，供 `superpowers-planner` 等代理编写 Spec/Plan 时使用。模板文件通过本 skill 的目录解析加载（相对路径解析到本 skill 目录）。

## 文档分工（MUST）

- **Spec（设计规范）面向人审**，**Plan（实施计划）面向 agent 执行**：两份**独立成文、不混写**。
- 两类文档头部均维护「版本历史」表：任何实质修订（含临时调整）必须**追加一行**并**递增版本号**，不得覆盖旧行。**澄清/草拟阶段（文档状态仍为 `draft`）的修订不记版本变更**：不追加行、不递增版本号，版本历史保持初始行；文档定稿（状态转 `active`）后才恢复版本记账。
- **关键来源/依赖一次写明（MUST）**：Spec 伪代码/方案与 Plan 任务中出现的每个数据来源、已查对象/集合、Mapper/Service/注入、取值与空值/边界，必须**就地写明它从哪来**（如：复用某方法已查的 `allBuidling`、`selectLmpBuildingByBuildingNo` 补列带出的 `system_id`、handler 已注入的 `reportMapper` 直调），写明「调谁/读谁/取谁」；**禁止**「由实施者处理」「此处待定/后续再定」「见后文」等留白半句。写完自查：每个符号的来源与依赖可逐行追溯、无遗留待问项。
- **多子功能需求：三层分工（MUST）**：需求含 **≥2 个「可独立验收」的子功能**时（粒度判据见 `feature-dev` 的「任务拆分」规则）：
  - **总览** `doc/features/<yyyy-MM>/<feature-name>/<yyyy-MM-dd>-00-overview-design.md`：按「**需求 → 改造点 → 影响接口**」组织，供评审快速建立全貌；
  - **子功能 Spec**：每个子功能一份 `<yyyy-MM-dd>-<sub-feature>-design.md`，按 Spec 骨架写实现细节；
  - **`README.md`**：**纯索引**（子功能表 + 归档 + 附属资源 + 关联背景），**不复述**总览或 Spec 的内容。
  三者职责不重叠：**总览讲「全貌与影响面」，Spec 讲「怎么实现」，README 只「指路」**。

## 模板文件（必须读取模板内容）

- **Spec 骨架**：`templates/spec-skeleton.md` —— 设计规范必须章节（需求分析(为什么改) / 方案选择 / 架构与设计(怎么改，含就地伪代码/SQL) / 接口与 API / 数据模型 / 风险与待拍板 / 测试与验收；11 章 + 文档头 + 版本历史），**审阅导向**
- **总览骨架**：`templates/overview-skeleton.md` —— 多子功能需求的总览（需求 / 改造点一览 / 接口影响总表 / 数据模型与 SQL 一览 / 子功能文档与审阅顺序 / 未决事项按改造点分布 / 已拍板口径速查），**评审全貌导向**
- **Plan 模板**：`templates/plan-skeleton.md` —— 实施计划文档头(含版本历史) / 硬性约束 / 文件结构映射 / 任务粒度 / 执行波次 / 范围外禁止，**执行导向**

## 高频返工点（写前警惕）

- **总览与 README 重复陈述同一事实**：两处都写「已拍板决策 / 待拍板项 / 数据模型 / 子功能说明」→ 后台必然漂移。**总览承载内容，README 只留索引与链接**。
- **第 1 章「需求分析」写超**：把接口拆分、字段清单、口径细节搬进 §1，与「方案选择」「接口定义」重复——每条控制在 1–2 句，方案归 §2、字段与 SQL 归 §4/§5；交稿前按模板「粒度约束」逐条勾选。

## 用法

0. **先判断是否拆分**：需求含 ≥2 个可独立验收的子功能 → 产出「**总览 + 各子功能 Spec + README**」三层；单子功能 → 只产出 Spec（无需总览）
1. 读取上述模板文件
2. 按骨架输出完整章节；某章节不适用时显式说明"不适用/无需"，不得省略整个骨架
3. 每次实质修订须同步在文档头「版本历史」追加一行并递增版本号（**澄清/草拟阶段的修订除外**：不记版本变更，见上「文档分工」）
4. **交稿前自检（MUST）**：交付用户前逐章回读模板章节点，命中以下任一项就地整改后再交付：
   - 每章只回答本章标题的问题（「需求分析」只写为什么改，不写方案、字段、SQL）；
   - 同一信息不在两章重复（方案只留在「方案选择」，字段与 SQL 只留在「接口/数据模型」）；
   - 第 1 章按模板「粒度约束」逐条勾选（句数上限、无表名/字段/SQL/口径、无分歧不写关键讨论）。
