# Java code ↔ msg 枚举生成

## 适用场景

- 新建 `code ↔ msg` 形式的枚举类
- 为已有枚举补全 `getByCode` / `getCodeByMsg` / `getMsgByCode` 查找方法

## 前置探查

生成代码前，按以下顺序探查项目环境：

1. **包路径** ：搜索项目已有枚举类所在目录（如 `**/enums/**`），动态确定 `package`，禁止写死
2. **Lombok** — 检查 `pom.xml` / `build.gradle` 是否包含 Lombok 依赖，决定是否使用 `@Getter`
3. **字符串工具** — 检查项目已有字符串工具类及依赖，按加载的规范选择现有工具或 Java 原生写法，不为生成枚举新增依赖
4. **代码格式** — 读取当前项目的 `AGENTS.md` 和平台专用规则，再检查同模块现有代码，确认行宽、链式调用、注解和格式习惯
5. **知识库规范** — 调用 `kb-loader` 解析 KB 根、项目与加载清单，先读最终根下的 `backend/java/index.md`，再实际读取 `backend/java/enum-standard.md`（规则、正确示例、例外及验证）和适用的格式规范；记录实际读取的规范路径。详细规则与模板只在 KB 维护，本技能不提供另一份正文

**KB 不可用**：遵循 `kb-loader` 的对应分支。未配置且无强制加载要求时，可按目标项目已确认的枚举规范处理，并注明未按 KB 验证；本次任务依赖 KB 特定模板而无法读取时，暂停依赖该模板的生成，不使用插件旧副本静默兜底。

## 生成步骤

1. 确认枚举名、用途及每个 `code` / `msg` 的来源；取值、空值含义或既有调用兼容性不明时先询问，不把示例值当作业务默认值。
2. KB 可用时，从已读取的 `enum-standard.md`「正确示例」生成，按其「例外」适配实际依赖；走允许的不可用分支时，仅使用目标项目已确认的规范。补全已有枚举时先读现有实现和调用方，只修改已授权范围。
3. 输出到探查到的枚举目录，核对包名、import 与实际依赖；汇报生成文件、取值依据及实际加载的规范。

## 交付核对

KB 可用时按其「验证」执行人工核对；走允许的不可用分支时按目标项目已确认规范核对并注明依据。重点不遗漏：

- 包路径及依赖来自目标项目，未新增依赖或写死示例路径。
- `getByCode` / `getCodeByMsg` / `getMsgByCode` 齐全，缓存、空输入、null msg 与无匹配行为符合已加载规范。
- 枚举常量按规范排序；修改既有枚举时核对受影响调用方。
- 测试、构建等命令遵守本次执行授权；未运行的验证明确注明，不将人工核对写成测试通过。
