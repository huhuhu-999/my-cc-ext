# JavaDoc 补充工具

负责扫描、补充与验证 JavaDoc。宿主支持且允许委派时按关联文件分配子代理；不支持、未授权委派或已受委派时，在当前会话串行执行相同规范。

## 规范加载

先调用 `kb-loader` 解析 KB 根、项目与加载清单，先读最终根下的 `backend/java/index.md`，再实际读取 `backend/java/development-standard.md`「文档注释（Javadoc）」章节及适用项目规则。详细风格、标签口径、继承/私有方法例外与示例只在 KB 维护；`templates/javadoc-examples.md` 保留为兼容引导页，不再是独立模板。

记录最终解析的规范路径及实际读取章节；委派时随文件清单传入，子代理也必须实际读取，不能只接收“已加载”摘要。KB 不可用时遵循 `kb-loader` 对应分支：未配置且无强制加载要求时，可按目标项目已确认的规范处理并注明未按 KB 验证；任务依赖 KB 特定模板而无法读取时，暂停依赖该模板的补充，不用旧副本静默兜底。

保留简短核对提醒：先读真实签名、实现与接口/父类注释，再判断是否需要补充；不得覆盖继承和私有简单转发的豁免，不能只凭名称猜业务口径。

---

## 工作流

### 第一步：确认范围（如有必要）

用户未明确指定范围时，用当前平台的用户提问能力确认；已指定则跳过。收集接口与对应实现，读取现有注释及实际行为。

### 第二步：收集候选

扫描脚本的执行仍需符合本次命令授权；未授权运行时不执行脚本，改用可行的文件读取收集候选，并在报告注明“扫描未运行”。

已获准扫描时，先定位当前已加载 `add-javadoc` Skill 所在目录，使用其中的脚本，以目标项目的已确认范围作为参数。仓库内开发时可用以下根目录相对路径（目标 `.` 或过滤模式须替换为本次范围）：

```bash
python skills/add-javadoc/scripts/scan_javadoc.py . --json
python skills/add-javadoc/scripts/scan_javadoc.py . --json -p "**/*Controller.java"
```

退出码 `0` 表示扫描器未报告缺失，`1` 表示扫描器报告类级或方法级缺失候选，`2` 表示至少一个文件解析失败。扫描结果只是线索：结合实际加载的规范、签名与继承链人工判断，不能强补已获豁免的注释；退出码 `0` 不代表注释语义完整，解析失败也不能视为文件无问题。

### 第三步：拆分子代理执行

先检查委派能力和当前授权。可委派时由主会话调度；不可委派或已受委派时直接执行下方文件修改规范，不递归委派。

将文件分批，每批包含 **1-3 个关联文件**（接口 + 对应的实现类打包在一起）：

1. 从扫描报告或人工读取结果中筛选实际需补充的文件，排除规范豁免项，按“接口名 - 实现类名”分组
2. 可委派时每组分配一个子代理，并发量不超过宿主当前可用额度；否则按组串行执行
3. 将已确认范围、最终解析的规范路径与章节、候选依据和本次执行授权传入下方 prompt；串行模式遵循相同边界

#### 子代理 Prompt 模板

```
你的任务是为以下文件补充 JavaDoc 文档注释。

## 要处理的文件

（列出文件绝对路径、接口与实现对应关系，以及扫描/人工读取得到的缺失候选和依据。已知 BOM 状态一并传入；未确认时标注未知，不猜测。）

## 必须遵守的规范

规范文件：<kb-loader 最终解析的 KB 规范绝对路径及章节；走允许的不可用分支时，列目标项目已确认规范的路径及依据，不虚构 KB 路径>
本次执行授权：<允许修改的注释范围；扫描等命令是否获准；委派限制>

先实际读取上述规范，再读取目标文件的签名、方法体和相关接口/父类注释，逐项判断候选是否确实需要补充。按规范保留继承及简单转发的例外，说明覆写的新增业务语义；标签与真实签名、返回值和异常对应。无法从代码或已确认需求确定的口径先报告，不编造。

若规范文件不可访问，回报阻塞，按主会话传入的、已依 kb-loader 确认的不可用分支处理；未配置且无强制要求时，仅可依据已确认并实际读取的目标项目规范，不声称已遵循 KB。依赖 KB 特定模板的工作保持暂停，不转读插件旧模板。

## 严格约束

- 已有完整注释的方法不要动
- 不要修改方法体代码
- 不要修改 // 行内注释
- 不要改 import、注解、字段
- 原文件无 BOM 时，保持 UTF-8 without BOM，禁止添加 BOM 头（EF BB BF）
- 原文件已有 BOM（扫描报告 hasBom: true 或其他已确认依据）时保留，不新增也不移除
- BOM 状态未确认且编辑方式不能保证保留时，先报告，不猜测或重写编码
```

### 第四步：汇总

所有文件处理完成后，按实际读取的规范人工核对注释与签名、实现及继承关系，并确认没有改动方法体等范围外内容；已授权运行扫描时复扫，仍将结果作为候选线索。报告列明规范豁免项、未解决项与解析失败，不以扫描无缺失等同语义完整。

输出汇总并注明委派或串行方式；数量从实际文件与改动逐项核对，未运行扫描时不填写扫描通过或虚构计数：

```markdown
## JavaDoc 补充报告

**加载规范**: <实际读取的路径与章节；未加载到时说明原因与影响>
**执行方式**: <主会话委派 / 当前会话串行>
**扫描结果**: <已运行结果与覆盖范围 / 未运行及原因>
**实际读取文件数**: N
**有缺失需补充**: N
**已补充文件数**: N
**已补充方法数**: N
**豁免与未完成项**: <按规范豁免的候选、解析失败、未确认口径及未执行验证>

### 文件处理详情

| 执行者 | 处理文件 | 类级 | 方法 | @param | @return | @throws |
|--------|----------|------|------|--------|---------|---------|
| <子代理或当前会话> | <实际文件> | <实际数量> | <实际数量> | <实际数量> | <实际数量> | <实际数量> |
```

## 子代理并行策略

| 总文件数 | 并发策略 |
|----------|----------|
| 关联接口与实现 | 同一组执行，避免注释不一致 |
| 独立文件组 | 按宿主可用额度分批并行 |
| 无委派能力或已受委派 | 当前会话串行完成全部已授权范围 |

每轮等待所有代理完成后再启动下一轮，避免并发过多。

---

## 约束

- 委派时主会话只做扫描、调度、验证与汇总；串行模式直接补充注释
- 原文件无 BOM 时保持 UTF-8 without BOM；已有 BOM 时原样保留，未知时不猜测
- 扫描及其他检查命令须符合本次授权；未运行就如实报告，不以本技能流程代替授权
