# 接口文档生成（前端对接用）

**定位**：把一个（或一组）Java Controller 端点，转成前端 / 联调方直接可用的 Markdown 接口文档。
**事实源**：字段、必填、错误码与文案**一律取自代码**，不臆造、不抄 PRD、不引用设计文档章节。

## 文件结构

```
gen-api-doc/
├── SKILL.md      # 本文件（流程、硬规则、坑位、落盘）
├── REFERENCE.md  # 读代码链路细则、表格写法与类型映射
└── EXAMPLES.md   # 文档骨架 + 单接口模板 + 完整产出示例
```

## 何时使用

- 用户给出 Controller 类或其中某个方法，要求「生成 / 补充接口文档」「前端对接文档」
- 新增或调整接口后，需要同步更新既有对接文档（在对应位置插入章节）

## 何时不使用

- 只需机器可读的接口契约（OpenAPI / Swagger 导出）→ 走项目既有 swagger 配置，不走本流程
- 接口字段语义尚未确定（设计阶段）→ 先出设计文档，再据此生成对接文档

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| Controller 类或方法 | 必 | 全限定类名或文件路径；只给某方法时定位到该端点 |
| 功能名 / 输出目录 | 选 | 优先按既有 `doc/features` 目录推断；无法确定时询问用户 |
| 既有接口文档 | 选 | 增量补充时提供，按其端点顺序插入对应位置，不一律追加文末 |

## 快速开始

用户：「给 `com.paic.pare.lmp.app.app.controller.WxminiReleaseController` 生成接口文档」

三步：

1. **读全链路** — 该 Controller 的端点清单与路径前缀 → 各端点的 Request / Response DTO → Service 里的错误分支（细则见「工作流」与 [REFERENCE.md](REFERENCE.md)）
2. **按「输出格式」逐接口成节** — 入参表 → 出参表 → 示例 → 错误码表；编号按端点出现顺序
3. **落盘** — `doc/features/<YYYY-MM>/<功能名>/<日期>-<功能名>-接口文档.md`；已有文档则**插入对应位置**，不追加文末

单接口的产出形态：

````markdown
## 3. 查询租赁位置与租期

**GET** `/wxrelease/rentUnitInfo`

### 入参
| 字段 | 类型 | 必填 | 说明 |

### 出参
| 字段 | 类型 | 说明 |

### 示例
**请求** → **成功响应** / **失败响应**（空数据场景另给一段）

### 错误码
| 错误码 | 文案 | 触发条件 |
````

> 完整产出（文首元信息、分组入参、元素小表、非统一响应体接口）见 [EXAMPLES.md](EXAMPLES.md)。

## 工作流

**读代码链路（缺一不可）**：`Controller → Request DTO → Response DTO → Service 实现 → 全局配置`，任何一环缺失都会让文档失真。

1. **Controller** — 类级 `@RequestMapping` 与方法级映射的 value 拼接出**完整路径**；HTTP 方法；每个参数的来源注解；返回泛型
2. **Request DTO** — `@Schema` 作说明、校验注解定必填 / 格式；嵌套对象与 `List<Xxx>` 元素展开成小表
3. **Response DTO** — `@Schema`；嵌套静态类与 `List<XxxResponse>` 的**元素结构**各起小表；枚举字段列出完整取值
4. **Service 实现** — 检索真实错误码与文案（`setPlaceHolder` / `businessError` / `BusinessException` / `ApiException`）
5. **全局配置** — context-path 拼进完整路径；序列化行为影响出参与示例

> 各环节的读取细则（注解清单、抽取要点）见 [REFERENCE.md](REFERENCE.md)。

## 文档骨架

整份文档 = **文首元信息块** + **接口节**（见下「输出格式」） + **附录**：

```markdown
# <功能名> - 接口文档

> 状态：draft
> 对应后端：<Controller 全限定类名>
> 请求前缀：/wmini/wxrelease              ← context-path + 类级映射拼出
> 请求头：accessToken: Bearer <token>       ← 鉴权方式；免登录接口要注明
> 【可选】⚠ 编号口径：……                    ← 编号依据；与 design/PRD 编号不同时在此说明

## 1. … ## 2. …                            ← 每个接口一节，按端点出现顺序

## 附录 A. 通用附件上传                     ← 跨接口复用的端点
## 附录 B：附件项结构                        ← 多处复用的字段结构
```

- **文首元信息**：状态 / 对应后端 Controller / 请求前缀 / 请求头（鉴权方式、是否免登录）。请求前缀由 context-path 与类级映射拼出。
- **版本历史（可选）**：文档进入增量维护后，用表格逐行记录接口契约的**增删改**，只写「变了什么」（路径 / 入参 / 出参 / 错误码 / 状态取值），不写实现细节、不引用设计文档；实质修订**追加一行并递增版本号**，不覆盖旧行，收尾回头核对文首元信息与各章表格。
- **附录**：跨接口复用的端点（如通用附件上传）与**字段内部引用的子结构**（如 `fileList` 的附件项）放附录，正文用「（见附录 B）」引用。**接口的主出参对象（`object` 本身及其数组元素）不得放进附录**——必须在各自接口的出参处展开字段表。
- **文内引用一律用路径**（`POST /wxrelease/applySubmit`），不用「接口 N」式编号，避免与外部文档编号口径混淆。

## 输出格式（每个接口固定一节）

编号按 Controller 中**端点的出现顺序**（1、2、3…），不按章节重排。每节固定四块：

```markdown
## N. 接口中文名

**POST** `/wmini/xxx/apply`

> 一句话说明（可选；多条业务规则可写成多行 blockquote）

### 入参
#### <分组名>              ← 入参字段多时按业务域拆多张表（如 位置与企业 / 申请内容 / 携带人与车辆）
**`<field>` 元素结构**     ← 嵌套对象 / List 元素另起小表（也可用 `#### <field> 元素`，同一文档保持一致）

### 出参
**`<field>` 元素结构**     ← 嵌套对象 / List 元素另起小表

### 示例
**请求** → **成功响应** / **失败响应**；空数据场景另给一段

### 错误码
```

四块的取值口径：

- **入参**：只列**前端要传**的字段。字段多时用 `#### 分组名` 按业务域拆表；嵌套对象与 `List<Xxx>` 元素展开成小表。无入参写「无。」
- **出参**：主出参对象（`object` 本身或其数组元素）必须在本节展开字段表（字段名 + 中文释义），**禁止只写「见附录 X」代替**；`object` 为数组时表前注明「`object` 为数组，元素结构如下」。字段内部引用的嵌套静态类与 `List<Xxx>` 元素结构各起小表，可引用附录。无业务数据写「无业务数据 —— 成功时 `object` 为空串 `""`。」
- **示例**：请求 / 成功响应 / 失败响应各一段。GET 请求用裸 URL 文本（`GET /path?a=1`），POST 请求用 JSON。**空数据场景单独给一段**（空对象把各字段列为 `""`、空数组给 `[]`）。
- **错误码**：逐条列真实文案与触发条件，见「坑位提醒」第 4、5 条。

> 极简或非统一响应体的接口（如直接返回图片 Base64）：出参用散文描述类型、「示例」给裸文本，四块可退化为粗体小节（`**入参**` / `**出参**`），但四类信息仍须齐备。

### 表格写法

- 字段名用**反引号**（`` `buildingId` ``）；类型**不加**反引号（`Long` / `String`）。
- 泛型在表格单元格里转义尖括号：写 `List&lt;String&gt;`（直接写 `List<String>` 会被 Markdown 当成 HTML 标签吃掉）。正文（非表格）里可写 `List<Xxx>`。
- 「必填」列用居中 `:---:`，取值 `是` / `否` / `条件`（`条件` 表示由其它字段决定，条件写在说明列）。
- 字段说明查不到时写 `—`，不臆造。

### 两条硬规则

- **入参不写服务端注入的参数**：`@CurrentUser` / 参数解析器注入的用户身份（如从 token 解出的 openId）、`@RequestHeader` 传递的鉴权头等，由框架注入或统一在文首「请求头」声明，**不进**入参表。
- **文档只写接口契约**：字段、取值、错误码、示例；不写服务端实现细节、不写 PRD 溯源、不引用设计文档章节。

## 坑位提醒（必须写进产出文档）

以下行为影响前端判空与类型处理，必须在文档中显式提示：

1. **统一响应体**：`{ "code": "SUC0001", "message": "", "object": ... }`。成功码 `SUC0001`，业务数据在 **`object`** 字段（不是 `data`）。
2. **null 序列化为空串**：全局序列化把 `null` 输出成 `""`；前端判空要兼容 `""`，不能只判 `null`。
3. **超长 Long 输出为字符串**：`Long` / `BigInteger` 且其十进制字符串长度 > 15 时输出为字符串（避免 JS 精度丢失），前端注意类型。
4. **成功码不代表有数据 / 成功**：无记录、无匹配、校验未通过、异常被吞后走成功分支时，都可能返回 `SUC0001`，要靠 `status` / `object` / `valid` 等业务字段判断。**这类分支要在相关示例或字段下加 ⚠️ 提示**，写法：`> ⚠️ **结论** —— 判断依据 + 前端分支`。
5. **业务失败码与平台码**：业务失败返回 `LMPxxxx` + `message`（文案可直接展示给用户）；未登录返回 `401 请先登录`，token 过期返回 `402 登录已失效，请重新登陆`。
6. **非统一响应体包裹的接口**：个别接口直接返回裸数据（如生成图片 Base64、下载文件），**不用 `JsonResult`**。其出参用散文描述类型、示例给裸文本，并注明「非 `JsonResult` 包裹；失败时返回统一错误响应体」。

> 上述取值是本项目（统一响应体 `SUC0001` / `object`、fastjson 序列化）已确认的行为；迁移到其他项目时先核对实际封装类与序列化配置，再落笔。

## 落盘约定

- **路径**：`doc/features/<YYYY-MM>/<功能名>/<日期>-<功能名>-接口文档.md`
  - `<YYYY-MM>`：当前年月，`doc/features/` 下第一层目录；`<日期>` 为 `YYYY-MM-DD`；目录不存在则创建
- **多个接口写在同一份文档**：按 Controller 端点出现顺序编号（1、2、3…），不按章节重排
- **增量补充**：**插入到对应位置**保持编号连续，不要一律追加文末；插入后回头核对全文编号
- 正文（说明、章节名）用**简体中文**；字段名、路径、错误码保持**代码原文**

## 纪律

- **数据来源唯一**：字段、必填、错误码、文案全部来自代码；查不到就留待确认，不臆造。
- **遵守「两条硬规则」**：入参不写服务端注入项；文档不写实现细节、不引用设计文档。
- **范围可控**：只给某方法就只出该端点；给了整个 Controller 就按出现顺序全出。
- **产出后自查**：编号连续、入参无注入项、每个「成功码无数据」分支已加 ⚠️、主出参对象字段表未被「见附录 X」替代、`List` 与嵌套对象均有元素小表、表格泛型已转义、文内引用用路径。
